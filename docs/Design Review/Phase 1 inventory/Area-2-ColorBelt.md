### Part C — Rulebook mismatches noticed in passing

**Private testing tab**
- **Two Add buttons when empty:** the header and the empty state both show a primary "Add private testing" (src/screens/testing/private/PrivateTestingTab.jsx:800-806, 845-855, 987). This breaks §1.1 (one visible button per action; max one primary). The approved P1 mockup draws both.
- **Rows don't behave like other lists:** no row click or detail view, no ↑ ↓ Enter, no N shortcut (src/screens/testing/private/PrivateRows.jsx:126, 167; src/screens/testing/private/PrivateTestingTab.jsx has no useRowArrowNav or useShortcutN). This breaks §8 (click a row to open it), §3.6 and v0.52 ("every later list reuses the same pattern").
- **Paid-on date unreachable on tablet:** the column is dropped and there is no detail view (src/screens/testing/private/PrivateRows.jsx:178-182). Breaks §1.3.
- **Cards don't filter** (src/screens/testing/private/PrivateTestingTab.jsx:864-876), unlike the event roster's cards. Breaks §8 (clicking a card opens the filtered list).
- **Past rows show two tags** (result or Cancelled + Paid/Not paid; src/screens/testing/private/PrivateRows.jsx:53-61, 177). Breaks §8 "one tag per row". The P7 mockup draws it, but the only recorded exception (v0.190) covers Grading rows.
