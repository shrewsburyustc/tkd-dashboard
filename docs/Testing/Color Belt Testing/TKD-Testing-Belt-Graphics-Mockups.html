Testing · Belt graphics — mockups for approval

Jae H. Jeong's U.S. Taekwondo Center · Color belt testing, Classes and ranks · guidelines v0.65 · October 17, 2026 · builds on the approved phase 1 design (v0.49)

Design only — not a working app. Nothing here is built or deployed. Each screen is shown at PC (1024px), tablet (768px), and phone (375px). Dashed amber notes are review callouts, not part of the design. Ranks and prices are Worcester's real list (old-system export, with the v0.62 seed changes).

What changed from the approved phase 1 design

  1. Belt graphics everywhere a rank appears (v0.64) — beside the rank name and beside its "Testing for" name; on the phone line 1 reads "[belt] Yellow → [belt] Orange". Names always stay. (Screen 1)
  2. Belt section in Add rank / Edit rank (v0.65) — pattern, belt color, middle stripe / bottom half color, end stripes 0–3 with their color, and a live preview with the rank name. A new rank copies the last rank's belt. (Screens 2–4)
  3. Staff see the belt read-only with a plain description, e.g. "Green with a white middle stripe". (Screen 5)
  4. Drag works on every device (v0.63) — tablet and phone rows now have a grip at the left (44×44 touch area); only the grip starts a drag. Class rows on touch screens get a grip too, so on the phone class names and ranks now start after the grip instead of at the 16px edge. (Screens 1, 6)
  5. Final award "None" (v0.62) — Deputy (last rank of Group D and Teen/Adult) shows a gray "No new rank" tag and no second belt. Deputy's price is $10 / $10 / $10.
  6. Save is blue whenever the form is valid (v0.57), even before anything changes; gray only while it can't be used (Add rank before a name is typed).
  7. Tab bar shows only "Classes and ranks" (v0.50) until Events is built.

Still needs your OK — small details I added

  1. Exact belt colors: white #FFFFFF, yellow #F2C200, orange #F07F13, green #2E8B3A, blue #1F5FBF, purple #6B3FA0, red #C8202A, brown #7A4A23, black #1F1F1F (chart below).
  2. Belt sizes: 40×12px in rows, 56×14px in dialogs; 1px #8F8F8A outline, 2px corners. Middle stripe is about the middle third of the inside (3 / 4 / 3px in rows, exactly 4 / 4 / 4px in dialogs); halves are exactly 50/50 (5 / 5 and 6 / 6px).
  3. End stripes: 2px bars with 2px gaps, 4px from the right end (3/3/6px in dialogs).
  4. Belt pictures don't count toward the 5-blue limit (like status tags) — a blue belt is a picture, not a UI signal.
  5. Swatch layout: all 9 colors in a fixed order (white → black). Mouse: 20px swatches in 28px buttons; touch: 28px swatches in 44×44 tap areas (5 per row on the phone, one row on PC and tablet). Each has its name as tooltip and screen-reader label, and the chosen name is written next to the row label ("Belt color Green").
  6. Selected swatch = dark ring (#1F1F1F), not blue — a blue ring would disappear around the blue swatch.
  7. End-stripe stepper uses − and + text, not ti-plus (that icon means "Add new"). − is gray at 0, + is gray at 3.
  8. Belt section order: right after Rank name (it's part of the rank's identity). PC dialog becomes two columns (rank details left, Belt right, 760px wide) so it still fits on screen; tablet dialog is one column, 520px wide, scrolling inside; phone stays full screen.
  9. Pattern control is a segmented control styled like the location switcher (selected = blue tint).
  10. "Testing for" in the dialogs shows the next rank's belt too.
  11. Staff description wording: "Solid blue", "Green with a white middle stripe", "Top half red, bottom half black", "Black with a white middle stripe and 2 yellow end stripes".
  12. Phone rows: line 1 wraps before the arrow when both names don't fit ("[belt] LT White" / "→ [belt] LT Yellow"); each belt stays next to its own name. Sparring gear is always text on the price line on the phone (no longer a tag), because line 1 is full with two belts; tags there are only Final award, No new rank and Not saved.

1. List with belts

Every rank shows its belt, and so does the rank it tests for — the belt change is visible at a glance. Names always stay.

What it does

  • Each rank row shows a small belt (40×12px) before the rank's name and another before its "Testing for" name: Yellow → Orange, Green → High Green (green with a white middle stripe), High Brown → Red / Black (top half red, bottom half black).
  • Big Stripe belts show 1, 2 or 3 yellow bars near the right end of the Bo Dan belt (black with a white middle stripe). Deputy is black with a yellow middle stripe.
  • The last rank shows the final award's belt (Group A: High Green → Blue). When the final award is None (Group D and Teen/Adult end with Deputy, which is practice for Dan testing), the row shows a gray "No new rank" tag and no second belt.
  • Phone line 1: "[belt] Yellow → [belt] Orange" with at most one tag (Final award / No new rank); prices on the next line, with "Sparring gear" as text at the end. When both names don't fit (the grip and Edit + ⋯ take 132px), the line breaks before the arrow.
  • Touch screens now have a grip at the left of every rank and class row (screen 6).
  • The tab bar shows only "Classes and ranks" until Events is built.

How staff use it

  • Nothing new to learn: the belts are pictures next to the names. Click / tap a rank to edit it as before (screen 2).

Rules applied

  • 10b v0.64 — belt beside the rank name and beside the Testing for name; phone "[belt] Yellow → [belt] Orange"; names always stay; standard belt colors; recorded exception to rule 7 — belts show real red, they are pictures, not UI signals.
  • 4 — meaning never by color alone: every belt has its name next to it.
  • 10b v0.62 — final award None → gray "No new rank" tag; Deputy $10 / $10 / $10.
  • 10b v0.63 — grips on every device (touch: 16px icon, 44×44 area, left of the row, never overlapping Edit + ⋯).
  • 10b v0.50 — only the "Classes and ranks" tab.
  • 8 — one tag per row; dense rows (40px mouse, 48px touch). 1.2 — blue count: rail, switcher, tab, Add class = 4 (belt pictures not counted).
  • Unchanged from the approved design (v0.49): page header Add class (v0.45), Final award tag, unsortable headers, phone 16px padding.

Still needs your OK

  • Belt sizes and colors; belt pictures not counted toward the blue limit; long phone names wrap at the arrow.

2. Edit rank — High Green

The rank dialog gets a Belt section. High Green is a middle-stripe belt: green with a white middle stripe.

What it does

  • Belt section, right after Rank name: a live preview (56×14 belt + the rank's name + a plain description), then:
  • Pattern — Solid · Middle stripe · Half and half.
  • Belt color — 9 standard colors; the chosen name is written next to the label ("Belt color Green").
  • Middle stripe color — shown for Middle stripe ("Bottom half" for Half and half), hidden for Solid.
  • End stripes — − 0 + (0 to 3). The End stripe color row appears only when it's 1 or more (default yellow, screen 4).
  • The preview updates as you click. The belt also updates in the list and in every rank that tests for this one after Save.
  • Save is blue straight away because the form is valid (v0.57); Save with no changes just closes.

How staff use it

  • Click the pattern, then the colors. Mouse: hover a swatch to see its name. Touch: tap a swatch (44×44 tap area); the chosen name shows next to the label.
  • Keyboard: Tab into a swatch row, arrow keys move the choice (radio group), the preview follows.
  • Save → "Rank saved · Undo" as before.

Rules applied

  • 10b v0.65 — Belt section built from parts: pattern, belt color (top half for Half and half), second color (hidden for Solid), end stripes 0–3 (yellow by default), live preview with the rank's name; fixed standard colors, each with its name shown. Admin only (v0.40).
  • 4 — never color alone: swatches have names (tooltip + label + text next to the row label); radio-group roles; 2.5 — 44×44 tap areas on touch.
  • 10b v0.46 — centered dialog over the dimmed list (PC two columns to fit), phone full screen. v0.57 — Save blue when valid.
  • 1.2 — dialog blue: Save + selected pattern segment, plus the Sparring gear box when ticked = 2–3 (the selected swatch uses a dark ring; belt pictures and swatches are not counted).
  • 8 — labels above controls; controls 32px (36px touch).

Still needs your OK

  • Belt section placement; PC two-column dialog; dark ring on the selected swatch; −/+ text stepper.

3. Add rank — copies Red, switched to Half and half

In Group B, "Add rank" starts as a copy of the last rank (Red): prices, sparring gear and the belt (solid red). The admin switches the pattern to Half and half to make a Red / Black belt.

What it does

  • A new rank's belt starts as a copy of the class's last rank — here solid red, with the hint "Copied from Red. Change if needed." An empty class starts as plain white.
  • Choosing Half and half renames the color rows: Top half (keeps red) and Bottom half (pick black). The preview shows the Red / Black belt with the typed name.
  • Save stays gray until a name is typed (v0.44); once "Red / Black" is typed it turns blue.
  • The new rank goes to the end of Group B: Red will test for it, and it tests for the class's final award (High Red).

How staff use it

  • Open Group B → Add rank → type the name → Pattern: Half and half → Bottom half: Black → Save.

Rules applied

  • 10b v0.65 — new rank copies the last rank's belt; empty class → plain white. v0.44 — prices and sparring gear copied; Save unavailable until a name is entered.
  • 10b v0.64 — Red / Black = top half red, bottom half black (exact 50/50).
  • 10b v0.46 / v0.57 — dialog; Save gray only while unusable.

4. Edit rank — Bo Dan - 2 Big Stripe

End stripes: Bo Dan (black with a white middle stripe) plus 2 yellow bars near the end.

What it does

  • End stripes is a small − / + counter from 0 to 3. At 1 or more, an End stripe color row appears (yellow by default; any of the 9 colors).
  • The preview shows the bars near the right end of the belt, as on the real Big Stripe belts.
  • Bo Dan - 1 / 2 / 3 Big Stripe differ only in the number of end stripes.

How staff use it

  • Click + or − to change the number of stripes; − is gray at 0 and + is gray at 3.

Rules applied

  • 10b v0.64 — Bo Dan - 1/2/3 Big Stripe = Bo Dan plus 1/2/3 yellow bars near the end. v0.65 — end stripes 0–3, color defaults to yellow, color row only when used.
  • 2.4 — no new icons: the counter uses − and + text (ti-plus means "Add new"). Each has an aria-label ("Fewer / More end stripes"); the number is announced when it changes.
  • 2.5 — touch: − and + drawn 36px with 44px tap areas.

Still needs your OK

  • −/+ text stepper; end-stripe size and spacing.

5. Staff view (read-only belt)

Staff see every belt in the list and, in the rank view, the belt with a plain description — no picker, no grips.

What it does

  • The list is the same as the admin list without edit controls or grips (v0.63: staff never see grips).

  • "Testing for" shows the next rank's belt too.

How staff use it

  • Tap a rank (or View on touch) → read → Close / back arrow.

Rules applied

  • 10b v0.40 — staff view only; v0.65 — picker is admin only; v0.63 — staff never see grips.
  • 4 — the belt is described in text. 6 / v0.46 — detail dialog with Close; phone full screen.

Still needs your OK

  • Description wording.

6. Drag on touch screens

Ranks and classes can be dragged with a finger on tablets and phones — but only by the grip, so scrolling the list still works everywhere else.

What it does

  • Every rank and class row on a touch screen starts with a grip (ti-grip-vertical, 16px icon, 44×44 touch area). Edit and ⋯ stay on the right, so the grip never overlaps them.
  • Only the grip starts a drag. Touching anywhere else on a row scrolls the page as usual; tapping the row still opens it.
  • While dragging, the row lifts (light gray, slight shadow), a blue line shows where it will land and the old spot fades. Near the top or bottom edge of the screen the list scrolls by itself.
  • Drop → saves at once with "Rank order saved · Undo" (5 seconds). A failed save shows the amber banner + Retry (rule 3.5).
  • Move up / Move down stay in the ⋯ menu on every device for keyboard and accessibility use.

How staff use it

  • Press and hold nothing special: put a finger on the grip and drag. Let go to drop.

Rules applied

  • 10b v0.63 — drag on every device, grip only, 44×44 touch area, auto-scroll near edges, saves on drop with Undo, Move up/down kept, staff never see grips; grip has touch-action: none (only the grip blocks scrolling).
  • 2.5 — 44px touch rows and tap areas. 1.2 — phone mid-drag blue count: bottom bar, switcher, tab, Add class, drop line = 5.

Still needs your OK

  • Touch class rows get grips too (class names move right on the phone).
