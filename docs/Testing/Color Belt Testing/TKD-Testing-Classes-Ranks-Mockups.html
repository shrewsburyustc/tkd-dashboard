Testing · Classes and ranks — mockups for approval

Jae H. Jeong's U.S. Taekwondo Center · Color belt testing, phase 1 · guidelines v0.47 · October 16, 2026 · revision 3 (your decisions applied)

Design only — not a working app. Nothing here is built or deployed. Each screen is shown at PC (1024px), tablet (768px), and phone (375px). Dashed amber notes are review callouts, not part of the design. Prices and ranks are Worcester's real list.

Decided (rulebook v0.41–v0.47) — drawn this way below

  1. Delete is permanent (v0.41). ⋯ → "Delete rank" / "Delete class" (red, ti-trash) → a confirmation that says exactly what happens. No Undo, no restore. Existing events keep their own copy. (Screen 7)
  2. Final award is a class setting (v0.42) — a dropdown in Edit class (optional in Add class). If it's not set, or its rank was deleted, the last rank shows an amber reminder; nothing is blocked. (Screens 4, 5, 7)
  3. Reordering is instant with Undo (v0.43). PC: drag ranks and classes by the grip. Every device: ⋯ → Move up / Move down. Ranks stay in their own class. A failed save shows an amber banner with Retry. (Screen 6)
  4. Add rank copies prices and sparring gear from the class's last rank (v0.44), and Save is unavailable until a name is typed. (Screen 3)
  5. "Add class" is a labeled primary button in the page header (v0.45); the N key triggers it on the PC. (Screen 1)
  6. Opening or editing a rank uses a centered dialog (v0.46) over the dimmed list, showing every field; full screen with a back arrow on the phone. Typed changes are never lost: Esc, clicking outside or the back arrow keeps it open with "Unsaved changes. Save or cancel first." (Screens 2, 3, 8)
  7. No "copy from the other school" for now (v0.47) — removed from this file.

Still needs your OK — small details I added

  1. A small gray "Final award" tag next to the last rank's "Testing for".
  2. Staff on a tablet or phone see a small "View" button on each rank row, so it's clear the row opens.
  3. Phone layout: 16px side padding; class names and ranks both start at that edge; the class chevron sits after the rank count.
  4. Rank table headers can't be clicked to sort — the rows are the belt order.
  5. Toast style: near-black with white text (same style as the rail tooltip); Undo only where the rule allows it ("Rank saved · Undo"), a plain toast after a delete ("High Green deleted").
  6. A row whose change didn't save gets an amber "Not saved" tag until Retry works.
  7. On the phone, if a rank already shows a tag (e.g. "Final award"), sparring gear is shown as text on the price line, so there's one tag per row.
  8. Save is drawn gray while it's unavailable (no name yet, or a field has an error).
  9. The red "Delete" button is the main button in the delete confirmation (red, not blue).
  10. In the rank dialog on PC and tablet the three prices sit side by side; on the phone they're stacked.
  11. The Edit class dropdown opens at the top ("Not set", then Little Tiger…) with a scroll bar.
  12. On the PC the class grip sits left of the chevron; rank names line up under the class name.

1. Classes and ranks — Admin

The school's list of Classes, their ranks in belt order, and the three prices for each rank. Any number of classes can be open at once.

What it does

  • Testing is a rail item (ti-certificate, "Testing"). The page has two tabs at the top: Events and Classes and ranks. This file only designs Classes and ranks; Events is designed in phase 2.
  • The heading shows which school's list you are looking at ("Testing" / "Worcester"). Each school has its own separate Classes, ranks and prices. Switch the location switcher to Shrewsbury to see and edit Shrewsbury's list.
  • Classes are a collapsible list in belt order: Little Tiger, White, Group A, Group B, Group C, Group D, Teen/Adult. Each line shows the class name and how many ranks it has. Click the chevron (or the class name) to open or close it; several can be open at once.
  • An open class shows its ranks as a dense table, in belt order: Rank, Testing for (the next rank — filled in automatically from the order), Early (paid in full before testing day), Testing day, Private (private testing), and Sparring gear (Yes / No).
  • The last rank of a class tests for the class's final award (Group A: High Green → Blue; Group B: Red → High Red; Little Tiger: LT Black → Yellow). It's set in Edit class (screen 5) and marked with a small gray "Final award" tag.
  • Events copy the prices when they are created. Changing a price or a rank here never changes an event that already exists — it only affects events created afterwards.
  • Tablet drops the two least-used columns (Private, Sparring gear); tap a row to see them in the rank dialog. Phone shows each rank as a two-line row: "Blue → High Blue" on top, the three prices underneath, and a "Sparring gear" tag when it's required. Class names and rank rows both start at the 16px gutter; the class chevron sits after the rank count, and the whole name area (48px tall) opens or closes the class.

How staff use it

  • Open a class to check or change a price before creating a testing event.
  • Click a rank row (or its Edit icon) to open it in a dialog (screen 2). ⋯ holds Move up, Move down and Delete rank.
  • Class line: the Edit icon opens Edit class — name and final award (screen 5); ⋯ holds Move up, Move down and Delete class.
  • "Add rank" under an open class adds a rank at the end of that class (screen 3). "Add class" (top-right, or press N on the PC) adds a new class (screen 4).
  • PC: drag a rank or a class by its grip handle to change the order (screen 6). Touch screens use ⋯ → Move up / Move down. Ranks stay in their own class.
  • Common tasks take 1–2 clicks: change a price = open class → click rank → type → Save.

Rules applied

  • 10b v0.38 — top tabs (Events, Classes and ranks); v0.39 — rail icon ti-certificate, label "Testing"; v0.36 — each school has its own list, following the location switcher; v0.40 — Admin edits, Staff view only (screen 8).
  • 6 / v0.45 — the add-new action is a labeled primary button in the page header ("+ Add class"), not in the top bar. 3.6 — N triggers the page-header add button (PC, when not typing).
  • 1.1 — one primary button ("Add class"); secondary actions live under ⋯; "Add rank" is an outline button.
  • 8 — dense rows (40px with a mouse, 48px on touch), 1px dividers, no card per row; columns ordered name → key info → actions. PC rank and class rows show grip + Edit + ⋯ = 3 controls (mouse limit 3); touch rows show Edit + ⋯ (limit 2).
  • 2.4 / v0.43 — ti-grip-vertical for drag to reorder.
  • 8 — max one tag per row; "Final award" and "Sparring gear" are neutral tags. On the phone, a final rank that also needs sparring gear (Group B: Red) keeps the "Final award" tag and shows "· Sparring gear" as text on line 2.
  • 1.3 — tablet drops low-priority columns, reachable through the rank dialog (v0.46: it shows every field); phone uses stacked rows; no horizontal scroll.
  • 2.1 — controls 32px (28px compact for "Add rank"), touch buttons 36px; 2.2 — icons 16px in rows, 18–20px in the rail; 2.5 — icon buttons draw a 28px square with an invisible 44×44 tap box on touch.

  • 6 — top bar has only the location switcher and the account avatar. 7 — sizes: page title 20px, row text 13px, labels and tags 12px; weights 400/500; sentence case.
  • 4 — every icon-only button has an aria-label (e.g. "Edit Yellow", "More actions for Group A", "Drag to reorder Yellow").

2. Edit a rank

Click or tap a rank to edit its name, prices and sparring gear. PC and tablet: a dialog opens in the middle of the screen over the dimmed list. Phone: full screen.

What it does

  • Shows every detail of one rank, including the columns the tablet and phone hide (Private, Sparring gear).
  • Rank name — must be unique within its class.
  • Testing for — read-only: "Orange — set by the rank order". To change it, change the order (screen 6).
  • For the last rank it reads "Blue — final award, set in the class settings" (tablet view below). The final award is changed in Edit class (screen 5), not here.
  • Prices: Early (paid in full before testing day), Testing day, Private testing — whole dollars. Side by side on PC and tablet, stacked on the phone.
  • Sparring gear required checkbox, and a gray line showing who last changed the rank and when.
  • Saving changes this list only. Events already created keep the prices they copied; new events copy the new prices.

How staff use it

  • Change the price → Save. The dialog closes and a toast "Rank saved · Undo" shows for 5 seconds (PC and tablet bottom-right; phone bottom-center above the bottom bar). Undo puts the old values back.
  • Cancel (or Esc, or clicking outside the dialog, or the back arrow on the phone) closes without saving — when nothing was changed.
  • Unsaved changes: if something was typed and you press Esc, click outside the dialog or use the back arrow, the dialog stays open and shows "Unsaved changes. Save or cancel first." (PC frame below). Nothing typed is lost; Cancel throws the changes away on purpose.
  • Errors show under the field as you type, in amber with a warning icon, and say what to do: "Group A already has a rank called Green. Try another name." (phone view). Save is grayed out until the error is fixed.

Rules applied

  • 6 / v0.46 — detail view is a centered dialog (12px corners) over the dimmed list, with Save + Cancel, showing every field; phone is a full screen with a back arrow (ti-arrow-left); unsaved-changes guard with the amber note.
  • 8 — labels above fields; fields 32px (36px on phones); errors under the field, validated while typing.
  • 1.4 — editing a field is reversible: Save, then a 5-second toast with Undo, no confirmation. Error text says what happened and what to do.
  • 7 — errors and the unsaved-changes note are amber with ti-alert-triangle + text, never red. 2.4 — Save uses ti-check (save only).
  • 8 — toasts bottom-right; phones bottom-center above the bottom bar (v0.29).
  • 5 — every change is logged with who and when ("Last changed by Main Admin").
  • 1.1 / 1.2 — the dialog counts as its own view: its one primary button is Save; the dimmed page behind isn't counted. No X in the corner — Cancel already closes it (one visible button per action).
  • 2.1 — the full-width Save is only on the phone (the one allowed full-width submit). 10b v0.36 — events keep their own copy of prices.

Still needs your OK

  • Prices side by side in the dialog on PC/tablet; Save drawn gray while unavailable.

3. Add a rank

"Add rank" under an open class opens the same dialog as Edit rank. Example: Group A is missing Orange, so the admin adds it.

What it does

  • Adds a new rank to the end of the class. The dialog says what will happen: "Added at the end of Group A. High Green will now test for this rank."
  • The class's final award stays with the class: the new rank becomes the last rank, so it now tests for the final award (Orange → Blue), and High Green now tests for the new rank.
  • Rank name starts empty. The three prices and the sparring gear setting are copied from the class's current last rank ("Copied from High Green. Change if needed."). There's no "last changed" line until it's saved.
  • Save stays gray until a name is typed (PC and tablet frames); once there's a name it turns blue (phone frame).
  • The new rank is at the end of the list; if it belongs somewhere else in the belt order, drag it into place (PC) or use ⋯ → Move up (screen 6).

How staff use it

  • Open the class → "Add rank" → type the name, check the prices → Save. The toast "Rank added · Undo" shows for 5 seconds.
  • Cancel, Esc, clicking outside or the phone's back arrow closes without adding anything (with the same unsaved-changes guard as Edit rank once something is typed).
  • The same name rule applies: "Group A already has a rank called Green. Try another name."

Rules applied

  • 10b v0.44 — added at the end; prices and sparring gear copied from the last rank; Save unavailable until a name is entered.
  • 6 / v0.46 — same centered dialog (PC/tablet) and full screen with back arrow (phone) as Edit rank.
  • 1.4 — adding is reversible: toast with Undo, no confirmation. 3.1 — smart defaults (copied prices; the class you opened).
  • 8 — labels above fields; errors under the field. 1.1 — one primary button in the dialog (Save). 2.1 — phone uses the one allowed full-width submit.

4. Add a class

"Add class" asks for the class name and, optionally, its final award. The new class appears at the bottom of the list, open, ready for its first rank.

What it does

  • Creates a new, empty class in the selected school's list (here Worcester). The only required field is Class name. The optional Final award after this class sits under a collapsed More details (closed on the PC frame, opened on the tablet and phone). A new class goes to the bottom of the list, so there's no next class to default from — the dropdown starts on Not set.
  • If the final award is left unset, the class's last rank shows amber "Final award not set — choose one in Edit class" in its Testing for (last frames). Nothing is blocked; it's a reminder until someone picks one in Edit class (screen 5).
  • Class names must be unique within the school. A duplicate shows "Worcester already has a class called Group A. Try another name." under the field.
  • The new class is added at the bottom of the list, opened, with its empty state: "No ranks in this class yet." and an "Add rank" button.

How staff use it

  • Click "Add class" (or press N on the PC) → type the name → Save (or Enter). Cancel or Esc closes without adding.
  • Phone: tap "Add class" → full screen with a back arrow → type → Save.
  • After saving, a toast "Class added · Undo" shows for 5 seconds. To move the class higher, drag its grip (PC) or use ⋯ → Move up.

Rules applied

  • 6 / v0.45 — labeled primary add button in the page header; 3.6 — N triggers it. 10b v0.42 — final award optional in Add class.
  • 8 — only ask what's required; optional fields are collapsed under "More details". 2.4 — ti-chevron-down / ti-chevron-up = expand / collapse.
  • 1.4 — adding is reversible: toast with Undo, no confirmation. 8 — empty state is one line + one action ("Add rank").
  • 1.1 — the empty-state "Add rank" is an outline button because "Add class" is already the screen's primary button.
  • 7 — dialog corners 12px (v0.29); 8 — labels above fields, fields 32px (36px on phones). 7 — the reminder is amber with ti-alert-triangle + text.
  • 2.1 — phone uses the one allowed full-width submit; PC and tablet dialog buttons are normal width (v0.28 pattern).
  • 1.2 — behind a dialog the page is dimmed and not counted; the dialog has one blue element (Save).

5. Edit a class (name and final award)

The Edit icon on a class line opens a small dialog with the class name and the rank students receive after the last rank of this class.

What it does

  • Class name — unique within the school.
  • Final award after this class — a dropdown of this school's ranks, grouped by class (this class's own ranks aren't listed), plus Not set. It starts on the first rank of the next class (Group A → Blue, the first rank of Group B); change it when that's not right (Little Tiger → Yellow skips White).
  • The list opens at the top: Not set, then the class headers in belt order starting with Little Tiger. A scroll bar shows there's more; the current choice (Blue, under Group B) is highlighted further down.

6. Reorder (and a failed save)

The order of the ranks is the belt order — it decides each rank's "Testing for". Continuing the example: Orange was just added at the end of Group A and is moved into place.

What it does

  • Changes where a rank sits in its class. "Testing for" is worked out from the order, so every affected rank updates by itself — no typing. Ranks only move within their own class; they can't be dragged into another class.
  • The change saves instantly and shows "Rank order saved · Undo" for 5 seconds. Undo puts the old order back.
  • The final award belongs to the class: it stays "Blue" and moves to whichever rank is now last (here back to High Green).
  • Classes reorder the same way: drag a class line by its grip on the PC (frame "Classes reorder the same way"), or ⋯ → Move up / Move down on any device. "Class order saved · Undo".
  • If a save fails (e.g. Wi-Fi drops): the moved row gets an amber "Not saved" tag and an amber banner stays at the top — "Rank order didn't save. Check the connection, then retry." — with Retry and a dismiss button. It never closes by itself.
  • Existing events are not affected — they keep their own copy.

How staff use it

  • PC: point at Orange's grip handle (tooltip "Drag to reorder"), hold the mouse button, drag up. The row lifts with a light gray background and a blue line shows where it will land; the faded row shows where it came from. Let go to drop. Esc cancels the drag.
  • PC keyboard, or anyone who prefers it: ⋯ → Move up / Move down (also on the PC menu).
  • Tablet and phone: tap ⋯ on the rank → Move up or Move down. Each tap moves it one place and shows the Undo toast. "Move up" is grayed out on the first rank, "Move down" on the last. The phone sheet ends with a Cancel row.
  • Failed save: tap Retry. Dismissing the banner leaves the "Not saved" tag on the row until it's saved.

Rules applied

  • 10b v0.43 — instant with Undo; grip handle on PC for ranks and classes; Move up / Move down in ⋯ on every device; ranks can't move between classes; failed save = amber row + banner with Retry.
  • 2.4 / v0.43 — ti-grip-vertical, ti-arrow-up, ti-arrow-down.
  • 1.4 — reordering is reversible: instant, 5-second Undo toast, no confirmation. 3.1 — inline in the list, no separate page.
  • 3.5 — a failed save is never silent: amber ti-alert-triangle, error banner with Retry (ti-refresh) that never auto-closes. 7 — amber, not red.
  • 2.5 — no drag-only actions on touch. 4 — works by keyboard only (⋯ menu).
  • 8 — touch rows: 2 visible actions (Edit + ⋯), the rest in ⋯; phone menu opens as a bottom sheet like the account menu (Home mockups); menu rows 44px on touch.
  • 1.2 — PC mid-drag blue count: rail, switcher, tab, Add class, drop line = 5.
  • 2.3 — the grip has a tooltip on hover/focus matching its aria-label ("Drag to reorder Orange").

7. Delete a rank or class

"Delete rank" and "Delete class" sit at the bottom of the ⋯ menu, in red. Deleting is permanent, so a confirmation says exactly what will happen first.

What it does

  • Delete rank takes the rank out of the class for good. The ranks around it close the gap and their "Testing for" updates by itself.
  • The confirmation names exactly what happens, e.g. "Delete High Green?" — "Green will test for Blue. Existing events keep their own copy. This can't be undone." Buttons: Cancel and a red Delete.
  • Delete class deletes the class and all its ranks: "Delete Teen/Adult and its 18 ranks? Group D's final award will become Not set. Existing events keep their own copy. This can't be undone." A class delete always names every other class whose final award it affects (Teen/Adult's first rank is Group D's final award).
  • Deleting a rank that another class uses as its final award (e.g. Blue is Group A's final award) is allowed. The confirmation says so — "Delete Blue? Group A's final award will become Not set. …" — and afterwards Group A's last rank shows the amber "Final award not set — choose one in Edit class" until someone picks a new one.
  • There's no Undo and no restore. After deleting, a short toast confirms it ("High Green deleted"). Existing events, registrations and results are unaffected — they keep their own copy. The deletion is written to the change log (who, when, what).

How staff use it

  • Click or tap ⋯ on the rank (or class) → Delete rank (or Delete class) → read the confirmation → Delete. Cancel (or Esc) backs out with nothing changed.
  • Deleted by mistake? Add the rank again with "Add rank" (or the class with "Add class").

Rules applied

  • 10b v0.41 — deleting is permanent: ⋯ → Delete rank / Delete class (red, ti-trash) → confirmation naming exactly what happens; no Undo, no restore; existing events unaffected; final-award case says the class's final award becomes Not set; logged.
  • 1.4 — not reversible → confirmation dialog, no Undo. 8 — no pop-up for success: a toast confirms it.
  • 7 — red (#A32D2D) only on delete: the menu item (pale red #FCEBEB on hover) and the Delete button in the confirmation. The final-award reminder is amber, never red.
  • 2.4 — ti-trash = delete. 7 — small confirmation dialog on all devices (12px corners).
  • 1.1 — the confirmation has one main button (red Delete); Cancel is secondary. 2.5 — menu rows 44px on touch.
  • 5 — every change is logged (who, when, what).

Still needs your OK

  • Red "Delete" as the confirmation's main button; plain toast without Undo after deleting.
