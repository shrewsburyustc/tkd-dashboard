Design only — not a working app. Nothing here is built or deployed. Each screen is shown at phone (390px, touch — the main device for families), tablet (820px, touch) and PC (1280px, mouse, in a browser). All names, dates, emails, the link and the reference number are made up; the street address is still to come from Jeffrey. “Today” is Sat, Oct 17, 2026. Parts with a dashed amber outline and a “Proposed: see N” label are proposals to confirm; DRAFT marks wording for Jeffrey to edit or replace.

The approved Form mockups (13 screens, v0.107) leave the school’s acknowledgment wording, the privacy note, the results-email lines, the top-star note, the “too many tries” and “unavailable” pages and the loading state undrawn, and two items amber (tablet sizes, the calendar’s keyboard use). The build plan (TKD-StarTesting-Remaining-Build-Plan.md §3, phase 4) lists them; F1–F6 draw each one.

Already decided — drawn this way below

  1. Form design approved (v0.107): 13 screens, two steps, white header strip (v0.106), event box leading with the testing (v0.99), “Location: <school>, <street address>”. Everything here reuses that file’s CSS and frames.
  2. Acknowledgment (v0.102, v0.107): required checkbox starting “I confirm these details are correct.”, then a drawn signature with Clear and the date added automatically; signer “the candidate, or a parent or guardian if under 18”; no typed fallback (“Can’t sign here? Please sign at the front desk.”).
  3. Privacy facts the note must match: date of birth and email are seen by staff and admins, only in the detail view (v0.160); signatures deleted 90 days after the testing day, everything else kept (v0.162); the database fixes ack_version = 'st-2026-10-18' (contract OPEN-3, build plan §4 M2).
  4. Results by email (v0.140, v0.141, v0.248): staff email each result from the school’s own email; Mark as sent.
  5. Can’t-register pages (v0.104) and the Send-time messages (Form screens 8, 12, 13) as approved. Color Belt’s live form (src/register/text.js) already uses “Too many tries from this connection…”, “This page didn’t load” and “Loading…”.
  6. Stars: only numbers below the Dan’s limit can be chosen (v0.100; database refuses the top star, contract §8.3).
  7. The dashboard calendar (v0.502, v0.503) is reused for date of birth; Form screen 4 is its approved look.
  8. The rate limit is shared with Color Belt’s form (20 an hour per connection, §8.3). The kill switch answers not_open.
  9. Unavailable, bad_request or invalid on Send show the approved “Sending failed” banner (Form screen 12), unchanged; the form switched off (STAR_PUBLIC_REGISTRATION off) shows the approved “Registration hasn’t opened yet” page, as Color Belt does.

Statuses the Function can answer (contract §8.2–8.4; Color Belt’s functions/_lib/register.js). Color Belt’s live wording is reused where it fits.

  • Form switched off (STAR_PUBLIC_REGISTRATION not on): the Function answers not_open, so families see the approved “Registration hasn’t opened yet” page — as Color Belt does (already decided; not drawn again).
