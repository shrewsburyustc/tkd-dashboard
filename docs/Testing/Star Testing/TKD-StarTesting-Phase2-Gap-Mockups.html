Star testing · Phase 2 gap mockups

Jae H. Jeong's U.S. Taekwondo Center · Star testing, build phase 2 (Events tab and the event page shell) · guidelines v0.500 · October 19, 2026 · Approved 2026-10-19 (v0.500) after a design review and Jeffrey’s screen-by-screen pass.

Design only — not a working app. Nothing here is built or deployed. Each screen is shown at PC (1280px, mouse), tablet (820px, touch) and phone (390px, touch). Event names, dates, times and people are examples. “Today” is Sat, Oct 17, 2026, as in the Events mockups. Amber text, and parts with a dashed amber outline and a “Proposed” label, are proposals to confirm; everything else is already decided.

The approved Events mockups (TKD-StarTesting-Events-Mockups.html, 14 screens, v0.92 / v0.107) leave a few states undrawn. The build plan (TKD-StarTesting-Remaining-Build-Plan.md §3, phase 2) asks for them before code: loading and “couldn’t load” for the Events list and the event page, an event deleted while its page is open, the Edit event hint when the closing date is unticked, and the open details of the two Edit event lines. Where Color Belt already does the same thing in the live app, these screens copy it and say so.

Already decided — drawn this way below

  1. Rule 3.4: a page shows content or a gray placeholder skeleton within 1 second, never a blank screen.
  2. Rules 3.5 and 8: errors are amber with ti-alert-triangle and words, stay on screen until fixed or dismissed, and offer Retry (ti-refresh) where it applies.
  3. Events tab and event page (v0.92, v0.99, v0.107): header “← Testing / Star testing”, Events · Rubrics and prices tabs, Upcoming / Past switch, rows, staff line; event page “← Star testing”, name, 14px summary line, outline Registration link button (under the summary on phones); Edit event fields (screen 7).
  4. Phase 2 event page has no tabs (no Candidates tab until phase 3; no placeholder tab or stand-in — rule P7, v0.50, v0.177).
  5. Registration (v0.85, v0.88): unticked, the switch alone decides; registration also closes by itself at the end of the testing day; opening is always by hand.
  6. Deleting (v0.91): admins delete from ⋯ on the Events list, after a confirmation; no Undo.
  7. Edit event lines (v0.92): “Rubrics and prices were copied when this event was created (date).” under the title and “Last changed by … · date” above the buttons, in Edit event only (screen 7). The build plan wrongly lists them as amber; only three details are proposals (G5).

Still to decide for phase 2 (asked separately)

  • How a sorted column header looks (Events mockups: “still open, designed once for all lists”). Not drawn here.

Proposals to confirm

  1. G1 Events tab loading: 3 gray placeholder rows in the list box; the Upcoming / Past switch and + Add event appear only once the list has loaded; the staff line still shows for staff. (All as Color Belt’s live Events tab.)
  2. G1 Events tab couldn’t load: the list is replaced by the amber banner “Couldn’t load events. Check the connection, then retry.” with Retry and no ✕. (Color Belt’s wording and look.)
  3. G2 event page loading: “← Star testing”, then gray bars for the event name and summary line; the Registration link button appears with the event. (Differs from Color Belt’s 4 list rows, because Star’s phase 2 page has no list.)
  4. G2 event page couldn’t load: “← Star testing” and the amber banner “Couldn’t load this event. Check the connection, then retry.” with Retry. (Color Belt’s wording and look.)
  5. G3 event deleted while open: on the next reload that answers not_found, the page shows only “← Star testing” and the gray line “This testing event was deleted, or the link is wrong.”; it does not move by itself; open dialogs close; no toast or banner. (Exactly Color Belt’s live behaviour.) Noticed within 15 seconds only once Star adopts v0.157’s refresh (proposed for phase 3); in phase 2 on tab return, unlock or reload.
  6. G4 closing date unticked: the date field disappears and a gray hint shows — Open: “Registration stays open until you close it, or until the end of the testing day.” Closed: “Registration stays closed until you open it.”
  7. G5 date: the date in “copied when this event was created (…)” is when the event was added (created_at).
  8. G5 staff changes: “Last changed by” counts staff Close / Open registration, so it can say “Staff”.
  9. G5 automatic close: not shown in “Last changed by” (it isn’t logged, OPEN-1).

G1. Star Events tab — loading, and “couldn’t load”

What the Events tab shows before its list arrives, and when the list can’t be loaded at all.

What it shows

  • Loading (top row): the page header and the Events · Rubrics and prices tabs show at once; the list area shows 3 gray placeholder rows (rule 3.4: content or a gray skeleton within 1 second). Screen readers hear “Loading events”. It is shown only the first time; later reloads are quiet (no skeleton, no flicker).
  • Proposed, as Color Belt’s live Events tab does today: the Upcoming / Past switch and + Add event appear only once the list has loaded (their counts and the copied Start time / Where need the list); the staff line still shows for staff (tablet frame, signed in as the desk account).
  • Couldn’t load (bottom row): the list is replaced by the amber error banner with Retry (rules 3.5, 8; the live ErrorBanner). It never closes by itself and has no ✕ here, because without the list there is nothing else on the tab to use. Proposed wording, Color Belt’s exactly: “Couldn’t load events. Check the connection, then retry.” If a later quiet reload fails while the list is already on screen, nothing changes on screen (the list stays).

Why

  • Not drawn in the approved Events mockups (build plan §3, phase 2 gap). Reusing Color Belt’s look keeps both testing sections the same.

G2. Star event page — loading, and “couldn’t load”

Clicking a row opens the event page (approved screen 11). This is what shows before the event arrives, and when it can’t be loaded.

What it shows

  • “← Star testing” shows at once (screen 11), so there is always a way back.
  • Loading (top row): proposed: two gray bars where the event name and the summary line will be (three on the phone, where the summary wraps). The Registration link button appears with the event, because it needs the event’s two links. Color Belt’s event page shows 4 gray list rows instead, because it has a Students list under the header; in phase 2 Star’s event page has nothing under the header (no Candidates tab until phase 3, no placeholder, rule P7, v0.177), so list rows would promise content that isn’t there.
  • Couldn’t load (bottom row): the back link and the amber banner with Retry, nothing else. Proposed wording, Color Belt’s exactly: “Couldn’t load this event. Check the connection, then retry.”
  • Once loaded, the page looks as screen 11 without the tab bar (see G3, top row).

G3. An event deleted while its page is open

Jeffrey has Winter 2027 Star Testing open on the office PC. Another admin deletes it from the Events list at the Shrewsbury desk (v0.91). Tablet: the desk account had the same page open.

What happens — the same as Color Belt’s live event page

  • Top row: the event page as it is in phase 2 — header, summary line and Registration link button, nothing under it (no Candidates tab until phase 3, P7).
  • Middle row: the next time this page reloads the event, the database answers not_found. Proposed (as Color Belt): the header, summary and button are replaced by the gray line “This testing event was deleted, or the link is wrong.” under “← Star testing”. The page does not move by itself, so the person sees why the event vanished; any open dialog (e.g. Registration links) closes. No toast, no amber banner: nothing of theirs was lost. The same line shows if someone opens an old bookmark or a mistyped address.
  • When it’s noticed: in phase 2 this page has no saves of its own (Copy link and Print flyer don’t write anything), so it is noticed on the next reload: coming back to the browser tab, unlocking the screen, or reloading the page. Once Star uses Color Belt’s 15-second quiet refresh (v0.157; the build plan proposes it for phase 3) it is noticed within 15 seconds. After not_found the page stops asking.
  • Bottom row: “← Star testing” goes back to the Events list (the address #testing/star), where the event is gone and the Upcoming count has dropped from 2 to 1. Nothing else changes there.
  • Same thing seen from the Events list (not drawn — already Color Belt’s behaviour): an Edit event save on a deleted event shows the dialog note “Someone else changed this just now. Your change wasn’t saved. Cancel, then open it again to see the latest.” (on phones, where the full-screen page has no Cancel: “… Discard changes, then open it again to see the latest.”) and the list reloads without it; a ⋯ action (Close / Open registration, Delete) shows the banner “Someone else changed this just now. Your change wasn’t saved.” and reloads.

G4. Edit event — closing date unticked

The admin unticks “Close automatically at the end of”. The approved Events mockups describe this hint but say it was “not drawn”.

What it shows

  • Proposed: when the box is unticked, the closing-date field disappears (as Color Belt’s live dialog) and a gray hint takes its place, under the box, at the same indent.
  • Proposed wording, depending on the Registration switch above it (v0.85: unticked, the switch alone decides; v0.88: registration also closes by itself at the end of the testing day):
    • Open (PC, phone): “Registration stays open until you close it, or until the end of the testing day.” — the wording already written in the approved Events details.
    • Closed (tablet, Winter 2027, never opened): “Registration stays closed until you open it.” — opening is always by hand (v0.85), so no date is mentioned.
  • The label “Close automatically at the end of” is the approved one (screens 4–7); only the hint under it is new.
  • Ticking the box again brings the date back: in Edit event, the closing date the event had when the dialog opened, otherwise 7 days before the testing date; in Add event, 7 days before the testing date and never before today (v0.85; this is what Color Belt’s live dialog does, EventsTab.jsx openEditEvent / changeValues). The hint changes as soon as the switch changes; it is not an error and never turns amber.
  • Color Belt’s live dialog shows no hint when unticked. If this is approved, Color Belt can take the same hint later (its own decision); nothing in Color Belt changes now.
  • The other fields, buttons and the unsaved-changes rule are exactly screen 7. The “copied” and “Last changed” lines are decided (v0.92); their details are G5.

G5. Edit event’s “copied when created” and “Last changed by” lines — the details to confirm

Both lines, their wording and their place in Edit event (screen 7) are decided by the v0.92 row. Only three details are proposals: what the date is, whether staff Open / Close counts, and leaving out the automatic close.

Already decided (v0.92)

  • Edit event shows “Rubrics and prices were copied when this event was created (date).” under the title and “Last changed by … · date” above the buttons, as approved screen 7. Edit event is admin-only (v0.86), so staff never see them. Screen 11 (event page) has neither line; nothing is added there.
  • Note: the build plan (§3, phase 2 row) lists these two lines as amber proposals and calls them an “event page line”. That is wrong: v0.92 decides their wording and place, in Edit event.

Proposed (amber outlines)

  • The date in line 1 is when the event was added (created_at, CONTRACT-0006), always with the year. It never changes: editing never re-copies (v0.61).
  • Line 2 counts every change a person makes to the event, including Close / Open registration from ⋯, so it can name a staff member or the desk account (tablet frame: “Last changed by Staff · Oct 16, 9:05 AM”). An event nobody has changed since it was added shows who added it. Time is Massachusetts time, the year only when it isn’t this year (as Rubrics and prices).
  • The automatic close (closing date or end of testing day) is not shown in line 2. Changes people make stay in the change log; the automatic close isn’t logged (CONTRACT-0006 OPEN-1).
