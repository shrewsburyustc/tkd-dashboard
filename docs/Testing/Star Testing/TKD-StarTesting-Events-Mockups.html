Star testing · Events tab — approved mockups

Jae H. Jeong's U.S. Taekwondo Center · Star testing, build phase 2 (Events) · guidelines v0.74 · October 17, 2026 · Approved 2026-10-17 after a screen-by-screen pass; updated the same day for one link per school (v0.80, v0.81): screens 2, 8, 9, 10, 11, 12 — approved 2026-10-17 (v0.89) (all 14 screens and the details below, incl. the amber proposals, except where a detail says it is still open)

Design only — not a working app. Nothing here is built or deployed. Each screen is shown at PC (1280px, mouse), tablet (820px, touch) and phone (390px, touch). Event names, dates, counts, the link and the QR code are examples (the QR code is not scannable). Unless a caption says otherwise, “today” is Sat, Oct 17, 2026. Amber text = was proposed here; approved with its screen.

The Events tab of Star testing: every star testing event, upcoming and past, how admins add, edit, open, close and delete them, what staff can do, and the event page's Registration link. It puts together the seven answers from TKD-StarTesting-Events-Questions.html. The public registration form, and the event page's Candidates, Grading and Results tabs, are designed next.

Already decided — drawn this way below

  1. Joint event, works on Both (v0.58); Events | Rubrics and prices tabs; event page with Candidates · Grading · Results (v0.60); each event copies rubrics and prices when created (v0.61).
  2. Registration (v0.67): Open / Closed switch, new events start Closed, optional automatic closing date (starts ticked, 7 days before testing, 11:59 PM Massachusetts time, never reopens; reopening after it removes it); ⋯ Close / Open registration with Undo.
  3. Roles (v0.68): admins add and edit events and open or close registration any time; staff close any time and reopen only before the closing date.
  4. Event fields (v0.69): name, testing date, start time, Where (both required, copied from the last event), Registration, optional note for families under More details; no per-Dan limit.
  5. Tags (v0.70): Not open yet → Open until … / Registration open → Registration closed → Testing today → Finished; registration also closes by itself at the end of the testing day.
  6. Upcoming / Past switch (v0.71), gray selected side; Upcoming soonest first, Past most recent first.
  7. Registration link (v0.72, v0.81): a button on the event page opening both school links side by side (QR code, link, Copy and Print per school); Copy Worcester link / Copy Shrewsbury link in ⋯; one flyer per school; icons ti-copy, ti-qrcode.
  8. Deleting (v0.73): admins can delete any event after a confirmation naming its candidates, payments and grades; no cancelled state.

Details (approved 2026-10-17)

  1. Rows. Event name (medium weight), testing date (“Sat, Nov 14, 2026”), candidate count, one tag. Click or tap a row (outside its icons) to open the event page. Row actions: PC and tablet show Edit and ⋯; the phone shows ⋯ only, with Edit event inside it (rules 2.5, 8). Columns are sortable; the starting order is v0.71's. Still open: how a sorted column header looks is designed once for all lists (Classes and ranks has no sortable headers yet).
  2. ⋯ menu (admin): Copy Worcester link · Copy Shrewsbury link · Close registration (or Open registration) · then, after a divider, Delete event (red). On phones Edit event is added above the divider (no Edit icon there). Rule 1.1: Edit is never both an icon and a menu item on the same screen.
  3. Empty states: no events at all: “No star testing events yet.” (admin; Add event stays in the header) or “No star testing events yet. An admin adds them.” (staff, without the gray staff line, since there's no ⋯ to use). One side empty: “No upcoming events.” / “No past events yet.” The Upcoming / Past switch shows from the start, with 0 counts.
  4. The very first event (nothing to copy from): Start time and Where start empty (“Choose…”) and Save stays gray until they're chosen. Later events copy both from the most recent event, with the hint “Start time and Where copied from Fall 2026 Star Testing. Change if needed.” (like v0.44).
  5. Start time is a dropdown in 15-minute steps from 8:00 AM to 8:00 PM; Where is a dropdown (Worcester school, Shrewsbury school). Both use the custom dropdown of v0.51. Date fields open the custom calendar that will be designed with the registration form (drawn closed here).
  6. Closing date follows the testing date until someone changes it: in Add event it starts 7 days before the testing date and moves with it; once edited by hand it stays put.
  7. Event names must be different (“There's already an event called Fall 2026 Star Testing. Try another name.”). Errors sit under the field in amber; Save is gray while any field has an error (v0.57).
  8. Edit event shows the same fields. Proposed: the line “Rubrics and prices were copied when this event was created (Oct 1, 2026).” and “Last changed by … · date” (as in Rubrics and prices); More details opens by itself when a note exists. Changing the date or Where never changes candidates.
  9. Past events: admins can still edit a past event (e.g. fix a typo) and delete it (v0.73). If its date is moved into the future it goes back to Upcoming. A past event's ⋯ menu has no Open / Close registration (registration closed by itself at the end of the testing day, v0.70): Copy registration link, and for admins Delete event (plus Edit event on phones).
  10. Unsaved changes (v0.46, v0.56): Esc, clicking outside or the back arrow with typed changes keeps the dialog open with the amber note “Unsaved changes. Save or cancel first.”; on phones the note also has a Discard changes link (screen 7).
  11. Closing date unticked: the hint reads “Registration stays open until you close it, or until the end of the testing day.” (v0.70). Not drawn on a screen; wording can be adjusted when built.
  12. Toasts (5 seconds, Undo, rule 8): “Registration closed · Undo”, “Registration open · Undo”, “Registration open. The automatic closing date was removed. · Undo”, “Event added”, “Changes saved”, “Link copied” (no Undo), “Event deleted” (no Undo).
  13. Staff (incl. the front-desk account): no Add event, no Edit icons; gray line “Staff can open or close registration from ⋯ until the closing date. Ask an admin to add or change events.”; after the closing date “Open registration” is grayed out with “The closing date has passed. Ask an admin to reopen.” (v0.68, drawn in the v0.66 grayed-item style).
  14. Event page: “← Star testing”, the event name, the summary “Sat, Nov 14, 2026 · 10:00 AM at Shrewsbury school · both schools · 23 candidates”, and the outline Registration link button (ti-qrcode) opposite the title. The summary line is 14px in the normal text color, not the small gray caption style, so the date and time are easy to read (Jeffrey, 2026-10-17). On phones the button sits under the summary line, so the date and time get the full width (Jeffrey, 2026-10-17); the link in the dialog wraps instead of being cut off on narrow phones.
  15. Registration link dialog: a line saying whether families can register right now: “Registration is open until Sat, Nov 7.” / “Registration is open.” / “Registration hasn't been opened yet, so families can't sign up.” / “Registration is closed, so families can't sign up right now.”, the QR code, the link, Copy link and Print flyer. Phone: full screen with the back arrow; PC and tablet: dialog with Close.
  16. The v0.72 proposals: (a) the link ends in a random code (/register/k7m2qx) so nobody can guess another event's link; (b) the old pages.dev address keeps working after the domain move so printed QR codes never break; (c) staff can see and copy the link; (d) Print flyer (screen 12) is included.
  17. Flyer: one letter-size page: school logo, “Star testing”, the event name, date and start time, Where, “Scan to register”, the QR code, the link, the note for families, and the closing date when set. Opens the browser's print dialog.
  18. Delete: confirmation “Delete Fall 2026 Star Testing? Its 23 candidates and their registrations, payments and grades are deleted too. This can't be undone.” with Keep event and red Delete event; for an empty event “It has no candidates. This can't be undone.” (v0.73).
  19. Failed save (rule 3.5): the row's tag becomes amber Not saved and an error banner with Retry stays until it works or is dismissed.
  20. Keyboard (PC): N opens Add event (admins only), ↑ ↓ move between rows and Enter opens the event page (v0.52), Esc closes dialogs (unsaved changes keep them open, v0.46).
  21. Change log: adding, editing, opening, closing (by hand or automatically) and deleting an event are all logged with who and when.

9. Reopening after the closing date (admin)
