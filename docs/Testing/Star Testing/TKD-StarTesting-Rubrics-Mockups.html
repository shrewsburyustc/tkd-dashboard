1. Rubrics and prices — Admin

The shared rubrics for 1st, 2nd and 3rd Dan star testing, the grade scale, the assistant-class table and the fees. One list for both schools.

What it does

  • Inside Testing → Star testing. A “← Testing” link above the title goes back to the Testing choice page. Two tabs: Events and Rubrics and prices (this one). This tab has no page-header button — there is nothing to “add” at page level.
  • The location switcher is on Both and the page works normally — star testing is joint, and these rubrics and fees are the same for both schools. A gray line says so: “Same for both schools. Events keep the rubric and prices they were created with.”
  • Three Dan blocks (1st, 2nd, 3rd Dan), each one line: chevron, the Dan, then a summary — “11 categories · 70 credits · pass 245 of 315 · up to 4 stars” — and an Edit icon at the right that opens Edit Dan settings. Click the chevron (or the Dan name) to open or close a block; several can be open at once.
  • An open block lists its categories in rubric order (the same order as the paper grading sheet): name, credits, and the most points it can give (credits × 4.5, e.g. “15 credits · max 67.5”). Assistant Instructor carries a gray “From class count” tag — its grade is never judged, it is worked out from the number of assistant classes.
  • Under the categories: “+ Add category” on the left and the running total on the right (“Total 70 credits · max 315”).
  • Below the Dan blocks: the Grade scale (A+ 4.5 … D 0, with the make-up rule written under it), the Assistant-class table (how many classes give which grade, for 12 and under and 13 and up) and the Fees per Dan (standard, same day, private). These three are always open.
  • Tablet shows the same thing with bigger touch rows, grip handle included. Phone also has the grip at the left of each category and shows each category as a two-line row (name, then “15 credits · max 67.5”); the Dan line has the name and chevron on top, the summary underneath and the Edit icon at the right; fees are one line of three prices — nothing scrolls sideways.
  • The extra frames at the end show the tightest sizes: a 1024px PC and a 768px tablet.

How staff use it

  • Open a Dan to check or change a category. Click a category row (or its Edit icon) to edit its name and credits (screen 2). ⋯ holds Move up, Move down and Delete category.
  • Reorder (screen 4): Drag by the grip on every device (mouse or finger). Only the grip starts a drag; touching elsewhere scrolls. Near the top/bottom edge the list scrolls automatically. Move up / Move down in ⋯ also works on every device (keyboard and accessibility).
  • The Edit icon on a Dan line opens Edit Dan settings — pass mark and highest star (screen 7).
  • The Edit icon on Grade scale, Assistant-class table, or a Fees row opens that editor (screens 8, 9, 10).
  • Every change here only affects events created after saving. Events that already exist keep their own copy, and finished results and recorded payments never change.

2. Edit a category

Click or tap a category (or its Edit icon). PC and tablet: a dialog in the middle of the screen over the dimmed page. Phone: full screen. Example: 1st Dan “Breaking” changed from 5 to 10 credits.

What it does

  • Two fields: Name and Credits (a number). Under Credits, a live line shows the most points the category can give — “Max points 22.5” for 5 credits, “Max points 45” for 10 — updating as you type.
  • If the change takes the Dan away from 70 credits, an amber note appears inside the dialog straight away: “1st Dan total will be 75 credits (usually 70). Max becomes 337.5; pass mark stays 245.” It is a reminder, not a block — Save still works.
  • Save is blue whenever the form is valid, even before anything is changed; Save on an unchanged form just closes the dialog.
  • Assistant Instructor (tablet frame): the same two fields — it can be renamed and re-credited — plus a read-only line “Grade comes from the assistant-class count.”
  • A gray line shows who last changed the category and when.

How staff use it

  • Change the credits → Save. The dialog closes and the toast “Category saved · Undo” shows for 5 seconds (screen 12).
  • Cancel, Esc, clicking outside or the phone's back arrow closes without saving when nothing was typed.
  • Unsaved changes: if something was typed, Esc / clicking outside / the back arrow keeps the dialog open with “Unsaved changes. Save or cancel first.” On the phone (no Cancel button) the note also has a “Discard changes” link that closes without saving (phone frame). The phone's own Back gesture does the same as the back arrow.
  • This same guard applies to every dialog in this file (screens 3, 7, 8, 9, 10).

Rules applied

  • 6 / v0.46 — centered dialog (12px corners) with Save + Cancel; phone full screen with back arrow; unsaved-changes guard. v0.56 — “Discard changes” link inside the note on phones. v0.57 — Save blue whenever valid.
  • 10b v0.61 — live totals while editing; 70 credits shown, not required; amber note with the exact wording; Assistant Instructor can be renamed/re-credited.
  • 1.4 — editing is reversible: Save, then a 5-second toast with Undo; no confirmation. 7 — the note is amber with ti-alert-triangle + text, never red. 2.4 — Save uses ti-check.
  • 8 — labels above fields; fields 32px (36px on touch). 2.1 — the full-width Save only on the phone. 5 — changes logged.
  • 1.2 — the dimmed list behind a dialog doesn't count toward the 5-blue limit; the dialog's one primary button is Save.

Approved 2026-10-17

  • Dialog subtitle “1st Dan · 7 of 11” (where the category sits); the “Grade” read-only label on Assistant Instructor; the “credits” word inside the Credits field.

3. Add a category

“+ Add category” under an open Dan opens the same dialog as Edit category, empty. The new category goes at the end of that Dan.

What it does

  • Name and Credits start empty. A hint says where it goes: “Added at the end of 1st Dan, after Korean Terminology.”
  • Save stays gray until both a name and credits are entered (PC frame). Once both are there it turns blue (phone).
  • As soon as credits are typed, the live line shows the max points, and — because the Dan was already at 70 — the amber note shows the new total: “1st Dan total will be 75 credits (usually 70). Max becomes 337.5; pass mark stays 245.”
  • Names must be different inside one Dan (tablet frame): “1st Dan already has a category called Breaking. Try another name.” — so the grading sheet never has two columns with the same name.
  • A new category is always judged (graded A+ to D on testing day). Only Assistant Instructor is worked out from the class count.

How staff use it

  • Open the Dan → “+ Add category” → type the name and credits → Save. Toast “Category added · Undo”.
  • If it belongs somewhere else in the rubric order, drag it into place by its grip or use ⋯ → Move up (screen 4).
  • Same unsaved-changes guard as screen 2.

Rules applied

  • 10b v0.61 — add categories with live totals; total shown, not required. v0.44 pattern — added at the end; Save unavailable until the required fields are filled.
  • v0.57 — Save gray only while it can't be used. 8 — errors under the field, amber, saying what to do.
  • 1.4 — adding is reversible: toast with Undo, no confirmation.
  • 1.2 — the dimmed list behind a dialog doesn't count toward the 5-blue limit; the dialog's one primary button is Save.

Approved 2026-10-17

  • Duplicate-name check inside a Dan; “Added at the end of …, after …” hint; new categories are always judged.

4. Reorder (and a failed save)

The order of the categories is the order of the paper grading sheet. Example: Knowledge is moved up to sit before Assistant Instructor; on the tablet, Breaking is moved down one place.

What it does

  • Changes where a category sits in its Dan. Categories only move within their own Dan; they can't be dragged into another Dan. Credits, max points and totals don't change — only the order.
  • The change saves instantly and shows “Category order saved · Undo” for 5 seconds. Undo puts the old order back.
  • If a save fails (e.g. Wi-Fi drops — phone frame): the moved row gets an amber “Not saved” tag and an amber banner stays at the top — “Category order didn't save. Check the connection, then retry.” — with Retry and a dismiss button. It never closes by itself.
  • Existing events are not affected — they keep their own copy.

How staff use it

  • PC: point at the grip handle (tooltip “Drag to reorder”), hold the mouse button, drag. The row lifts with a light gray background, a blue line shows where it will land, and the faded row shows where it came from. Let go to drop. Esc cancels the drag.
  • Drag by the grip on every device (mouse or finger). Only the grip starts a drag; touching elsewhere scrolls. Near the top/bottom edge the list scrolls automatically. Move up / Move down in ⋯ also works on every device (keyboard and accessibility).
  • Tablet: press the grip with a finger and drag (frames 3 and 4). Phones drag the same way — the grip sits at the left of each category row (phone frame). The grip has a 44×44px touch area on touch screens.
  • Move up / Move down: each tap moves the category one place and shows the Undo toast. “Move up” is grayed out on the first category, “Move down” on the last.
  • Failed save: tap Retry. Dismissing the banner leaves the “Not saved” tag on the row until it's saved.

Rules applied

  • 10b v0.61 / v0.43 — reorder by grip, Move up / Move down in ⋯ on every device; instant with Undo; failed save = amber row + banner with Retry. Owner decision: drag works on every device — changes v0.43 (“touch screens use ⋯”) dashboard-wide, recorded as v0.62.
  • 1.4 — reordering is reversible: instant, 5-second Undo toast, no confirmation. 3.1 — inline in the list.
  • 3.5 — a failed save is never silent: amber ti-alert-triangle, error banner with Retry (ti-refresh) and dismiss (ti-x) that never auto-closes. 7 — amber, not red.
  • 2.5 — 44×44px touch area on the grip; no drag-only actions (⋯ always offers Move up / Move down); touch rows show grip + Edit + ⋯. 4 — works by keyboard only (⋯ menu). 8 — one tag per row (“Not saved” wins).
  • 1.2 — mid-drag blue count (every device): rail, switcher, tab, back link, drop line = 5 (the limit).
