Staff accounts — Reset password and Reset PIN · mockups for approval

Jae H. Jeong's U.S. Taekwondo Center · guidelines v0.75 · October 17, 2026 · decisions v0.70–v0.75 (questions file TKD-Staff-Accounts-Questions.html)

Approved 2026-10-17 (v0.76), design only — not a working app. Nothing here is built or deployed. Each screen is shown at PC (1280px, mouse), tablet (820px, touch) and phone (390px, touch). Dashed amber notes are review callouts, not part of the design. Example accounts: Main Admin (jberg412@gmail.com, you), Grandmaster (second admin, v0.23 — drawn as an example), Staff (shared front desk).

What this part of Staff accounts does

  • Lets an admin fix the two things people forget: the password (signs in) and the PIN (unlocks the lock screen). Nothing else yet — adding, disabling and editing accounts wait for personal logins (v0.70).
  • Replaces the SETUP.md SQL snippets for the desk password and PIN. Those stay in SETUP.md as an emergency backup only.

How an admin uses it (≤ 3 clicks to the dialog, rule 3.1)

  1. Initials circle → Staff accounts (under "Admin").
  2. Find the person → ⋯ (or click/tap anywhere on the row) → Reset password or Reset PIN.
  3. Step 1: type your own password (v0.74). Step 2: the new password (type it or Generate, then Copy) or the new 4-digit PIN. Done: a 5-second toast says what happened.
  4. Tell the person the new password / PIN in person. For the desk: type the new password once on each desk device (they were all signed out, v0.72), then the desk PIN.

2. Staff accounts page

A page (not a rail section): opened from the account menu. Lists every dashboard account.

  • Title "Staff accounts", gray line under it: "Reset a password or PIN when someone forgets it." No page-header button (nothing to add yet, v0.70).
  • Each row: name → email → one tag (Admin, Staff or Shared; Shared wins for the desk, rule 8 one tag) → ⋯. Sorted: admins, then staff, then shared, each A–Z. Only name, email and role — no PIN or password details are ever shown (nobody can see them; they're one-way hashes).
  • Your own row shows "(you)" and has no ⋯: you change your own password and PIN from your account menu (v0.71). An invisible spacer keeps the tags lined up.
  • Click or tap anywhere on a row opens the same ⋯ menu (there is no detail view yet — exception to rule 8, for your OK). ↑ ↓ + Enter work on PC (v0.52); Enter opens the menu. Your own row isn't clickable and ↑ ↓ skip it.
  • Location switcher stays in the top bar but doesn't change this list: accounts belong to both schools (exception to rule 3.3, for your OK).
  • Rail: no section is highlighted — Staff accounts isn't a rail section. Leaving: click Home / Testing in the rail (or browser Back).
  • Loading: gray placeholder rows (rule 3.4). Failed to load: amber banner "Couldn't load staff accounts. Check the connection." + Retry (rule 3.5). Opened by a non-admin (typed address): the page shows "Only admins can see Staff accounts." — the database refuses the list anyway.

4. Reset password — step 1: your password

  • Title "Reset password", then a who-line (initials, name, email) for the person being reset — it stays on both steps so nobody resets the wrong account.
  • "Step 1 of 2" · heading "Confirm it's you" · "Enter the password you sign in with." (same words as Change PIN) · field Your password (dots; focused). Cancel + Continue (gray until something is typed; Enter = Continue).
  • Checked the same way as Change PIN (signs you in again with it; v0.28). That also gives the database the "password within 10 minutes" it requires (v0.74).
  • Wrong password: field clears, amber "That password doesn't match. Try again." (shown on the phone). Too many tries: Supabase's own limit — amber "Too many tries. Wait a few minutes and try again."
  • PC/tablet: dialog with Cancel (no X), Esc cancels. Phone: full screen, back arrow = Cancel on step 1, single full-width Continue.

5. Reset password — step 2: the new password

  • "Step 2 of 2" · "Choose a new password for Staff." · one field New password, shown in plain text (v0.73), in the normal font (rule 7: one font family). Generated passwords are lowercase words only, so there is no l/1 or O/0 to confuse.
  • Under the field: Generate (ti-wand) fills in 4 easy words joined by dashes (e.g. plum-ladder-quiet-river, 20+ characters); press again for another. Copy (ti-copy) copies the field; the button reads "Copied" for 2 seconds (same icon). Both are plain outline buttons.
  • Typed passwords: a live count under the field, "12 characters minimum (8 so far)" in gray; it turns into green text "Long enough" at 12 (words, not color alone). Reset password (blue) stays gray until 12+.
  • Gray line above the buttons: "Staff will be signed out on every device. Save the new password before you continue — it won't be shown again." For the shared desk it ends with "Type the new password on each desk device."
  • "Back" text link (next to Cancel) returns to step 1; phone back arrow does the same on step 2.
  • Unsaved changes (v0.46 / v0.56): once step 2 has a password in the field, Esc, a click outside the dialog or the phone back arrow keep the dialog open with the amber note "Unsaved changes. Save or cancel first." (phone: plus a "Discard changes" link). Only Cancel / Discard closes it, so a password already copied into the password manager is never silently thrown away. Same for Reset PIN once a digit is in.
  • Can't reach the server / it fails: the dialog stays open with the password still in the field and an amber "Couldn't reset the password. Nothing was changed. Try again." (+ Retry = the same button). Never silent (rule 3.5).
  • Password is the same as the person's current one? Not checked — the database can't tell without trying it; harmless.

6. Reset password — done

  • The dialog closes; a 5-second toast (no Undo — a reset can't be undone, and the confirmation is the two-step dialog): "Password reset for Staff. Signed out on 3 devices." (1 → "Signed out on 1 device."; 0 → just "Password reset for Staff."). PC/tablet bottom-right, phone bottom-center above the bottom bar (v0.29).
  • Behind the scenes (v0.71/v0.72, one all-or-nothing step): new bcrypt hash saved, emailed sign-in links cancelled, the person signed out everywhere, change-log line "Main Admin reset the password for Staff" (never the password).
  • The signed-out desk devices show the sign-in screen within about a minute.

7. Reset PIN

  • Same two steps: step 1 your password (identical to screen 4, not drawn again), step 2 the new PIN (v0.75).
  • Step 2: "Choose a new 4-digit PIN for Staff." and the hint "Not all the same (1111) and not a straight run (1234)." The digits are shown, not dots (the admin is choosing it for someone else and has to read it out). PC: the same 4 boxes, typed from the keyboard (Backspace removes the last digit). Tablet/phone: the same boxes plus the approved keypad (36px keys, 44px tap areas; Del removes the last digit).
  • No auto-save on the 4th digit (unlike Change PIN): the admin checks the digits, then presses Reset PIN. Gray until 4 digits.
  • Too easy: the 4 digits stay, amber "That PIN is too easy to guess. Choose another." (shown on the phone), Reset PIN gray.
  • Shared desk: gray line "This is the shared front-desk PIN. Tell the desk staff the new one." Personal accounts: "Tell Grandmaster the new PIN."
  • Done: toast "PIN reset for Staff. Works on every device now." Nobody is signed out. A device that hit 5 wrong PINs stays locked and needs the password (0002 rule) — not mentioned in the toast; it's in SETUP.md.

9. Details to approve

  1. Staff accounts is a page opened from the account menu (no rail icon, no rail item highlighted).
  2. Rows: name · email · one tag (Admin / Staff / Shared) · ⋯; your own row says "(you)" and has no ⋯.
  3. Exception to rule 8: clicking/tapping a row opens its ⋯ menu (no detail view yet); your own row isn't clickable.
  4. Exception to rule 3.3: the location switcher stays visible but doesn't filter accounts (they belong to both schools).
  5. A who-line for the person being reset on both steps of both dialogs.
  6. New password shown in plain text (normal font); Generate (ti-wand) = 4 easy words joined by dashes; Copy (ti-copy) shows "Copied" for 2 seconds.
  7. Live "12 characters minimum (N so far)" → green "Long enough"; Reset password gray until 12.
  8. Warning line before saving: signed out everywhere, save it first, it won't be shown again (+ desk line).
  9. Success toasts: "Password reset for Staff. Signed out on 3 devices." / "PIN reset for Staff. Works on every device now." — 5 seconds, no Undo.
  10. Reset PIN digits are shown (not dots) and need a press on Reset PIN (no auto-save on the 4th digit).
  11. Unsaved-changes guard on step 2 (Esc / outside / back arrow keep it open; phone "Discard changes").
  12. Failure keeps the dialog open with what was typed and an amber "Couldn't reset … Nothing was changed. Try again."
  13. Icons added to the map in v0.73: ti-wand (Generate), ti-copy (Copy / Copied). No ti-check outside save/done; toasts have no icon (as approved).
