## 1. Data layer (Builder B) — `src/lib/blackBelt/api.js`

### 1.1 Rules for every function
- One async function per database call used in B1, **camelCase object arguments**, always resolving to `{ status, …}`; **never throws**. A network failure or an answer that isn't a JSON object with a known `status` → `{ status: 'error', error }`.
- Real mode: `supabase.rpc(name, args)` with the **exact** argument names of 0016 (`p_…`). `bb_cycles_list` runs the purge (volatile): a normal POST, **never** `rpc(…, {}, { get: true })`. Table reads use explicit column lists (granted columns only — `select('*')` is refused); never `date_of_birth`, `email_for_results`, `requirements` on staff screens, any login id.
- Preview mode: the same calls reach `mockBlackBelt.js` through `mockClient.js` (§2); the data layer has **no** preview branch of its own except `schoolToday()` (pretend date, as `eventsApi.schoolToday`).
- **Money:** whole cents everywhere (`87000` = $870). Prices: `money.js` `parsePrice(text)` → `{cents}` or `{problem: 'empty'|'notWhole'|'notNumber'|'tooLow'|'tooHigh'}` ($1–$5,000 whole dollars, = `bb_price_is_valid`); `formatDollars` from `src/lib/money.js` for display. (Color Belt's `parseDollars` stops at $1,000 — not used.)
- **Dates:** `'YYYY-MM-DD'` text = Massachusetts school dates; "today" = `schoolToday()`. Times `'HH:MM'` (the database sends `'12:30:00'` from tables → cut to 5). Never `new Date('YYYY-MM-DD')` for a school date (UTC shift).
- Rows → app objects in camelCase (shapes in §1.3). Answers from RPCs keep their numbers; snake_case keys are converted.

### 1.3 Shapes
- **CycleState** (from `bb_cycle_state`, also computed client-side by `rules.cycleState(cycle, days, today)` with the same rules): `{state: 'past'|'testing_today'|'open'|'closed_by_date'|'not_open_yet'|'closed', registration, past, testingToday, firstDay, lastDay, nextDay, publicStatus: 'open'|'not_open'|'closed'|'finished', closedOn}`.
- **CycleSummary** (`bb_cycles_list` row): `{id, name, state: CycleState, firstDay, lastDay, nextDay, dayCount, applicationDue, registrationOpen, autoClose, candidateCount (active, both schools), hasPayments, hasFormWaivers, version}`.
- **CycleDetail**: `{id, name, applicationDue, submissionsDue, autoClose, registrationOpen, firstOpenedAt, codes: {worcester, shrewsbury}, pricesFrom, version, createdAt, updatedAt, createdByName, updatedByName, state: CycleState, candidateCount (active), candidateCountAll, days: Day[], plans: Plan[], kukkiwon: {1,2,3,4: cents}}`.
- **Day**: `{id, name, date, start, end, place: {code}|{other}, second: {start, end, place}|null, parts: ('physical'|'technical'|'curriculum')[], version}` — ordered by date, start, id.
- **Plan**: `{id, name, position, paymentsCount, payments: [{id, paymentNo, dueOn, followsApplicationDue, version}], amounts: {1: [cents…], 2: […], 3: […], 4: […]}}` — ordered by position.
- **CycleForm** (what Add / Edit cycle edit; `rules.js` turns it into the 0016 payload): `{name, applicationDue, submissionsDue, autoClose, registrationOpen, days: Day-like (id null for new), plans: [{key, id|null, name, payments: [{paymentNo, dueOn, followsApplicationDue}], amounts}], kukkiwon, pricesFrom}`. In Edit cycle `plans`/`kukkiwon` are read-only and only `due_dates` are sent.
- **Waiver**: `{id, versionName, body, isPlaceholder, supersededAt, createdAt, createdByName}`.

### 2.2 Rules it enforces (same order and statuses as the SQL — §1.1 of CONTRACT-0016)
- Check order in every function: 1 `ctx.hasDataAccess` → `no_access` · 2 role (`ctx.isAdmin`) → `not_allowed` for A · 3 input → `invalid` (the same `rules.js` checks + 0016's key-by-key payload check: unknown keys, wrong types) · 4 row → `not_found` · 5 version → `stale` · 6 data rules · 7 `duplicate_name` (normalized, case-insensitive) · 8 write. Locks don't exist in the browser (one tab at a time); everything else is copied.
- **Cycles:** add creates closed, `first_opened_at` null, two unique 8-character codes from `[a-hjkmnp-z2-9]` (unused in either column of any cycle), `requirements` copied from the source cycle or the starting point, `prices_from`; days not before today; 1–20 days; 1–10 plans; 1–12 payments; `follows_application_due` only on payment 1 and only = Application due; deadlines not after the last day; part on no day → `{status: 'part_without_day', parts}` (in the order physical, technical, curriculum). **Prices are written only by add and never change (v0.902):** update with `plans` / `kukkiwon` / `prices_from` → `invalid`; update matches days by id (an id of another cycle → `invalid`), needs every `(cycle_plan_id, payment_no)` once, refuses a **changed** date before today, keeps unchanged past dates, keeps `due_on = application_due` while the flag is on; bumps the version once when anything changed, nothing when nothing changed.
- **Registration:** `past` → `finished`; opening while the current waiver `is_placeholder` → `waiver_needed`; opening after Application due with auto close on → admins only (staff `not_allowed`) and auto close turns off; first opening sets `first_opened_at`; same value → no write.
- **Delete cycle:** version and the count of **all** candidates → `stale`; any `bb_payments` row → `has_payments`; any drawn waiver → `has_waivers`; else removes the cycle and everything under it.
- **Waiver:** stale current id → `stale`; body 1–20 000 after trim; same text → no write; else supersede (`superseded_at = now`) + new version named by the year rule.
- **Keep years:** both empty or both 3–20, else `invalid`; first call → `confirm_needed` + the count (candidates not yet purged whose purge date under the new numbers is ≤ today); a different confirm count → `stale`; then save and **run the purge** (DOB, email → null, `personal_removed_at`; drawn waivers' signature and signer name → null, `removed_at`).
