Finance · Daily report: a payment that was edited and then undone (U-1) — two ways to show it

  • The bug (NOW): after Edit payment and then the toast's Undo, the money is right ($70.00), but the row still has the Edited tag and reads “Was · edited by Jeffrey Berg · Thu, Nov 5”, with nothing after “Was”. The payment detail shows Edited next to the amount too. It happens in every section with Edit payment (Camps shown; Black Belt probably the same).
  • A — show it as a plain payment (recommended): when nothing differs from the first payment, the row has no tag and no second line, and the detail has no Edited tag. The detail's History still lists both changes, so nothing is hidden from an admin who checks. Pros: the report only flags what really changed; nothing to read for a change that cancelled out. Cons: the edit is visible only inside the detail.
  • B — say it was changed back: the row keeps the Edited tag, and the second line reads “Changed back · edited by Jeffrey Berg · Thu, Nov 5”; the detail keeps its tag. Pros: the edit stays visible on the report itself. Cons: an extra tag on a payment that is exactly as first recorded; one more sentence to learn.
  • Both are screen-only (no database change). The printed page uses the same row text, so it follows the choice.
