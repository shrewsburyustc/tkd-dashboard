## 0054 — `0054_finance_event_report.sql`

Adds **new** functions and ONE new table. Replaces **no** live Finance function. Reads only through the live internal `public.finance_money_rows_core(p_location_code, p_from, p_to, p_source, p_owner)` (0052's version), so every rule (which payments count, undone / edited / refund / returned-check states, the school stored on each payment, names) is exactly Finance's.

### New table `public.finance_event_exports` (model: `finance_exports`, 0011 section 2e)
One row per event CSV download: `id uuid pk default gen_random_uuid()`, `source text not null` (check in 'color_belt','star','camp','black_belt','board_breaking'), `event_id uuid not null` (NO foreign key on purpose: events live in five tables), `event_name text not null`, `location_code text null` (FK to `public.locations(code)`; NULL = both schools), `row_count integer not null check (>= 0)`, `downloaded_at timestamptz not null default now()`, `downloaded_by uuid null default auth.uid()` (a login id, never returned), `downloaded_by_name text not null`. Append-only with the same guard trigger function `public.finance_append_only()` as `finance_exports`. RLS on; policy `to authenticated using ((select public.has_data_access()) ...)` select only for admins is NOT needed: follow `finance_exports` exactly (read: same policy as that table; no insert/update/delete policy; writes only through the security-definer function). Revoke all from public, anon, authenticated (and service_role where 0003/0011 does); no grant to anon. Add to the change-log trigger setup the same way `finance_exports` is (check how 0011 does it).

### `public.finance_event_report(p_source text, p_event_id uuid, p_location_code text default null) returns jsonb`
`language plpgsql stable security definer set search_path = ''`; `revoke ... from public, anon, authenticated, service_role; grant execute ... to authenticated`.
Checks in this order, each returning `{status: ...}`:
1. `has_data_access()` not true → `no_access`
2. `is_admin()` not true → `not_allowed` (staff never see the report)
3. `p_source` not one of the five, or `p_event_id` null → `invalid`
4. `p_location_code` not null and not in `public.locations` → `not_found`
5. the event does not exist in its table (`color_belt`→`testing_events`, `star`→`star_events`, `camp`→`camps`, `black_belt`→`bb_cycles`, `board_breaking`→`brk_events`) → `not_found`

Rows = `finance_money_rows_core(p_location_code, null, null, p_source, null)` filtered to `event_id = p_event_id` (Color Belt private testing rows have no event id and so never appear; a Star private candidate belongs to its Star event and does appear, flagged `is_private`). Each payment counts on the day it was paid (`day`), at the school stored on it (`school`).

Returns on `ok`:
```
{ status:'ok', source, school: p_location_code|null,
  event: { id, name },
  totals:  { count, total_cents, in_cents, net_cents,           -- same meaning as finance_day.totals
             cash:{count,cents}, check:{count,cents}, card:{count,cents} },
  refunds: { count, cents, cash_cents, check_cents, card_cents },  -- same as finance_day.refunds
  returned: { count, cents },                                     -- Black Belt returned checks that count, as finance_day
  by_school: [ { school, <same totals/refunds/returned keys as above> } ... ],   -- one entry per school that has rows (only the asked school when p_location_code is given); ordered Worcester, then Shrewsbury
  days: [ { day, <same totals/refunds/returned keys>,
            items: [ <exactly the keys of one finance_day item: source, payment_id, day, time, first_name, last_name,
                      what, event_date, is_private, kind, method, amount_cents, state, was_amount_cents, was_method,
                      was_school, moved_to, moved_from, changed_by_name, changed_on, recorded_by_name,
                      PLUS school, PLUS the camp / black belt / board breaking extras finance_day adds
                      (for_items, one_payment_plan, handed_in_on for black belt)> ... ] } ... ],   -- days newest first; items ordered like finance_day (recorded time, last name, first name, payment id)
  generated_for_day: testing_today() }
```
Counting rules are Finance's (see `finance_figures_from`): only rows with `counts` add to totals; `item`/`count` ignore returned checks; refunds are `kind='refund'`; net = total_cents. `generated_for_day` is not needed — omit it. No fingerprint (this report closes nothing).

### `public.finance_event_export(p_source text, p_event_id uuid, p_location_code text default null) returns jsonb`
`volatile security definer`; same checks 1–5 as above (admin only). Returns `{status:'ok', source, event_name, school, rows:[…]}` where each row has exactly the keys of one `finance_export` row (day, school, time, first_name, last_name, what, event_date, is_private, was_school, kind, method, amount_cents, counted_cents, recorded_by_name, state, note, event_name, plus the black belt extras) ordered by day, recorded time, last name, first name, payment id. Inserts ONE row into `finance_event_exports` (with `set_config('tkd.action','finance_event_export',true)` and a `tkd.batch_id`, then cleared, like `finance_export`). Exception block like `finance_export`'s (`stale` / `invalid`).

## 0055 — `0055_black_belt_roster_paid_on.sql`

Replaces **only** `public.bb_cycle_roster(uuid)` (0025's version, section 9i). Same signature, rules and grants. Adds ONE key to each roster row: `paid_on date` = the day of the candidate's **last counting payment** (kind 'payment' that still counts, not undone, not reversed by a returned check — use the same "counts" rule `bb_candidate_money` uses), shown by the app only when the candidate is paid in full, `null` when there are no counting payments. The app shows the date only when `money` says the balance is 0; the database does not decide that. No table changes; touches no other section. Tests: `supabase/tests/0055_tests.sql`, `step0055`, fingerprints file, SETUP section `## Migration 0055: Black Belt roster paid date`; a candidate with one payment, two payments, an undone payment, a returned check and none.
